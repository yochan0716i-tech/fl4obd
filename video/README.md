# video — ドラレコ映像 × OBD テレメトリ

走行動画にテレメトリ（パワーフロー・マップ）を重ねるためのツール群。

- **再生**：ブラウザ（Chrome / Win・Mac、Android も再生のみ可）。エンコード不要。
- **書き出し**：ブラウザでテレメトリ動画を書き出し → ローカル ffmpeg 1コマンドで合成。

同期の根拠・機器特性は `vehicle-knowledge/dashcam-obd-time-sync.md`（プライベート）に記録。

## 構成

| ファイル | 役割 |
|---|---|
| `../video.html` | **再生アプリ**（1920×1080 のステージをそのまま再生。書き出し対象と同一の絵） |
| `../lib/flow.js` | パワーフロー描画。`replay.html` と `video.html` が共用（コピーしない） |
| `sync.js` | 時刻同期＋テレメトリ派生の中核。環境非依存の ES モジュールで、**再生アプリ（ブラウザ）と CLI（Node）が共用** |
| `build-sync.mjs` | `sync.json` を生成する CLI |

## 再生アプリ（`video.html`）

レイアウトは 1920×1080 固定で、**画面に見えているものが書き出し結果と同一**になる（操作バーはステージ外なので映らない）。

```
┌──────────────────────────┬─────────────┐
│  前方カメラ 1280×720      │ パワーフロー │
│  （原寸・無加工）          │  640×720    │
├─────────────┬────────────┼─────────────┤
│ リアカメラ   │ ナビ        │ 俯瞰        │
│  640×360    │  640×360   │  640×360    │
└─────────────┴────────────┴─────────────┘
```

パワーフロー図の左下の空きに **Gボール（前後左右G）** を表示する。データはドラレコ内蔵IMU
(`$GSENS` 10Hz)。**ドラレコ自身の NMEA 由来なので映像と同一時間軸**でオフセット補正が不要。
軸とスケールは GPS 由来の加速度と突合して校正済み（X=前後 r0.925 / Y=左右 r0.806、単位は g）。
ボールは**体が押される方向**に動く（制動で前＝上、右旋回で左）。フルスケール ±0.5g（実測の
横G最大が約0.4g）。描画は `lib/flow.js` 内なので**再生アプリと書き出しの両方に自動で乗る**。

前方・リアは同名クリップで**長さ・境界が完全一致**（実測 全29本で差 0.000s・`creation_time` 同一）
なので、リアは前方の `currentTime` に追従させる（0.15s 以上ずれたら合わせ直す）。リアが無い機種・
欠けクリップではそのセルを黒のままにする。同名 MP4 が複数ある場合はパス階層が浅い方を前方、
次をリアとして扱う（ディレクトリ名に依存しない）。

使い方: OBD ログ (.txt) と GPX を選び、**ドラレコの SD カードのフォルダを選択**（Chrome の
`showDirectoryPicker`）→「読み込み」。フォルダ選択が使えない環境（Android など）は MP4 と NMEA を
複数ファイル選択で渡す。OBD ログの時間帯に一致するクリップだけを自動で拾うので、SD 全体を
入れてよい。

読み込みは2パス構成。SD には数日分が入っているため、**1st: NMEA の先頭 4KB だけ読んで開始時刻で
候補を絞り、2nd: 生き残りだけ全文解析**する（実測で 188本 → 53本、**全文解析を72%回避**）。
ファイル名の書式には依存しない。**開始時刻が取れなかったクリップは必ず候補に残す**——録画開始
直後は GPS 未測位（`$GPRMC` の status=V）で先頭に有効 fix が無いことがあり、実測でも188本中10本が
該当した。落とすと取りこぼす。最終採用クリップが全件解析と一致することを実データで確認済み。

- クリップは `<video>` 2枚のダブルバッファで繋ぐ（境界の 4 秒前から次を先読み）。前方・リアで各2枚。
- 動画が時刻の主体（マスタークロック）で、テレメトリがそれに追従する。
- 操作: 再生/一時停止（Space）、±5/10秒（←→）、シーク、1x/2x/4x、`sync.json` のダウンロード。
- 同期の警告（`ok:false` など）は操作バー下部に表示される。

## 動画の書き出し

再生アプリの「⤓ 書き出し」から。**テレメトリだけを JPEG 連番で書き出し、映像との合成はローカルの
ffmpeg 1コマンド**で行う（ローカル依存は ffmpeg だけ・Win/Mac 共通）。

オーバーレイは **1本のファイル**に書き出す。第1候補は **WebCodecs で符号化した生 H.264
(Annex-B) エレメンタリストリーム** で、`ffmpeg -f h264` が直接読めるため**コンテナもマクサも
外部ライブラリも不要**。フレーム間圧縮が効くので実測でも MJPEG の 1/3 以下になる（テスト
パターンで 603MB vs 1.46GB、実際のオーバーレイは大半が静止なのでさらに小さい）。
WebCodecs が使えない環境では **MJPEG を1本のファイルに連結**して代替する（`-f mjpeg`）。
どちらも単一ファイルで、連番ファイルは作らない。

書き出す画は 640×1440 の縦積みで、**映像領域は書き出さない**（黒の無駄が無い）:

```
y    0- 720  パワーフロー 640×720
y  720-1080  俯瞰        640×360
y 1080-1440  ナビ        640×360
```

出力先フォルダに以下が生成される。

| ファイル | 内容 |
|---|---|
| `overlay.h264` (または `overlay.mjpeg`) | テレメトリ（既定 10fps、単一ファイル） |
| `concat_front.txt` / `concat_rear.txt` | 前方・リアの concat リスト（絶対パス） |
| `compose.txt` | 実行する ffmpeg コマンド（trim 範囲・crop・overlay 位置を埋め込み済み） |
| `sync.json` | 同期マニフェスト |

`compose.txt` の最下部にある **ffmpeg 行を「1行のまま」出力先フォルダで実行**すると
`out.mp4`（1920×1080 / 30fps）ができる。黒背景に 前方(0,0) → リア(0,720) → 右カラム(1280,0)
→ ナビ(640,720) の順で重ねる。

- **1行にしてある理由**: 行継続記号が Windows(cmd/PowerShell) と Unix で異なるため、1行が唯一の
  Win/Mac 共通形。
- **`-nostdin` を付けている理由**: 付けないと、コマンドの後に続く行を ffmpeg が**対話コマンドとして
  読み取ってしまう**（`Parse error, at least 3 arguments were expected` が出る）。説明コメントも
  コマンドより前に置いてある。
- 実行中の `Auto-inserting h264_mp4toannexb bitstream filter` は concat デマクサの**正常な情報表示**。
- バッチファイル(.bat)に貼る場合のみ `%06d` を `%%06d` に書き換える（対話実行なら不要）。

### SD の絶対パス欄について

concat リストに絶対パスを書く必要があるが、**File System Access API はハンドルから絶対パスを
返さない**（`.name` だけ）。そこで最初に選んだフォルダ名から自動補完する:

- **macOS**: リムーバブルは必ず `/Volumes/<名前>` にマウントされるので `.name` から確定的に組める。
- **Windows**: ドライブレターは名前から導けないため初回だけ手入力。
- 入力値は `localStorage` に記憶し、次回以降は自動で入る（別の SD に差し替えたら名前で判定して推定し直す）。

### 地図タイルと帰属表示

操作バーのセレクタで **ダーク / ダーク(地名なし) / ライト(OSM)** を切り替えられる（`localStorage` に記憶。
書き出しは押した時点の選択を使う）。既定は **ダーク(地名なし)**——UI が暗色なので馴染み、走行線が映え、
公開時に地名が写らない。

- OSM 公式タイルは**ライトのみ**。ダークは OSM データを使った CARTO の basemap
  （`basemaps.cartocdn.com/dark_all` / `dark_nolabels`）。**APIキー不要**で
  `access-control-allow-origin: *` なので canvas 描画（書き出し）も通る。
- **帰属表示は再生・書き出しの両方で必ず出す**（マップセル右下）。地図画像を含む成果物を
  配布する以上必須。文言はスタイルごとに持つ（`© OpenStreetMap contributors` ／ CARTO 使用時は
  `© CARTO` も）。
- OSM 公式タイルの利用ポリシーは「アプリを識別できる UA・帰属表示・キャッシュ・バルク取得禁止・
  heavy use 禁止」。本アプリは1走行あたりユニーク約350枚＋キャッシュなので **low-volume の
  範囲**に収まるが、常用するなら基図配信を前提とした CARTO 側が筋が良い。

### 実装メモ

- マップは Leaflet の DOM をラスタライズできないため、書き出し経路では `video/tilemap.js` が
  **canvas に自前描画**する。OSM タイルは CORS 許可（`access-control-allow-origin: *`）なので
  canvas は汚染されない。
- **タイル取得はルート全体でユニーク約350枚**（実測）。以降はキャッシュヒットなので、連番書き出しでも
  取得回数は増えない。
- **マップの縮尺は「書き出しボタンを押した時点の再生アプリの表示状態」に固定する**（俯瞰は
  ズーム＋中心、ナビはズーム。中心は自車追従）。再生アプリのマップセルは 640×360 で書き出し
  キャンバスと同寸なのでズーム値をそのまま流用できる。**書き出す前に好みの縮尺へ調整してよい**。
  自前のタイル描画は整数ズームのみ対応なので丸める。
- マップが未生成の場合のフォールバック算出では、ナビのズームは**短辺(360px)基準**にする。
  Leaflet の `getBoundsZoom` は縦横両方が収まる最大ズームを選ぶため、幅基準にすると1段ズレる。
  なお読み込み直後は再生アプリと算出値が一致する（実測: 俯瞰 z10・中心ずれ 0m、ナビ z15）。
- パワーフローは SVG を data URL 化して画像として描く（`lib/flow.js` をそのまま使う）。
  **OBD サンプルが変わらない間は再ラスタライズしない**（OBD は約1.84Hz、出力は10fps なので効く）。
- **SVG に `position:absolute` 等の位置指定を残してはいけない**。単体画像として描画したとき
  root ごと画面外に飛び、**完全に空白**になる（実際にこれでパワーフローが出なかった）。
  隠すための style はラッパー `<div>` に置き、`svgDataUrl` でも `style` を落としている。
- 俯瞰は自車以外が静的なので**一度だけ描いて毎フレーム転写**する。

## sync.json の生成

```sh
cd video
node build-sync.mjs --obd ../logdata/fl4obd_YYYY-MM-DDThh-mm-ss.txt \
                    --dashcam /Volumes/<SDカード> \
                    [--channel REAR] [--gpx <path>] [--out sync.json]
```

- ドラレコフォルダ配下を再帰探索し、MP4 と同名の `.NMEA` を対応付ける（フォルダ構成に依存しない）。
- `--gpx` 省略時は OBD ログと同じ basename の `.gpx` を自動で探す。無ければマップは NMEA を使う。
- `--channel` は使うカメラの絞り込み（パスの部分一致）。既定はパス階層が浅い方＝通常は前方カメラ。

## 汎用性（特定のログ・動画に依存しない）

データから導出するもの（**ハードコードしない**）:

- セッション分割（NMEA の連続性）と、OBD 区間と最も重なるセッションの自動選択
- クリップ長（`duration_ts/time_base` を1本ずつ）。1分/3分/5分設定や末尾の切れも吸収
- アンカー `A`（`NMEA先頭 − S0` の外れ値除去平均）。NMEA のみを使うので `creation_time` がローカル時刻の機種でも正しい
- `NMEA先頭 − creation_time`（**セッション毎に変わる**ので診断値として実測。定数化しない）
- スマホ時計オフセット `D_obd` / `D_gpx`（NTP 状態で変わるので毎回実測）
- 多チャンネル機（前方/後方が同名）や `EVENT`/`PARKING` の複製は**時間重複で自動除去**
- 車速ソースは `22_2920` → 無ければ `01_0D` にフォールバック。ISO-TP の宣言長も決め打ちしない

機器プロファイルとして持つもの:

- `cVideo`（映像 t=0 のオフセット）。実測 +0.4±0.6s のため既定 **0**。GPS 同期時計を撮影して校正すれば 1フレーム=33ms で確定できる。

## 信頼性

`sync.json` には各推定の**残差・サンプル数・谷のコントラスト・実測か否か**が入る。停車ばかりの回などで解けない場合は `ok:false` と `warnings` で明示し、壊れた値を黙って通さない。
